# ConfigLens correctness, release and privacy audit — 2026-10-12

## Scope and method

The checkout began clean at `f8c6ae7`. When unrelated concurrent edits appeared, the staged audit
was copied into a separate worktree, with the original checkout and a private backup preserved.
The delivery branch is `codex/audit-filesystem-release-privacy-verified`. Unrelated dependency,
source and website edits are excluded; this audit does not push main or modify old release assets.
No `AGENTS.md`, `CLAUDE.md` or `.cursorrules` was present in tracked files or the repository's
ancestor directories. Contributor instructions, decisions and implementation status were read first.

Review covered the Rust CLI, discovery/adapters, filesystem policy, context/snapshot paths,
release scripts, dependency policies, all five workflows, tests, build scripts, project documentation
and website checks. Suspected defects were reproduced with synthetic regression tests, not real
client configuration. Runtime client conformance is still not claimed.

The privacy pass examined 2,624 initially tracked files and filenames, synthetic fixtures,
fuzz artifacts/logs, generated website output, four tracked raster images and their metadata,
reachable Git object contents, commit messages and author/committer metadata. After fetching the
configured origin refs, the initial non-shallow census was 41 commits and 3,184 unique blobs.
Gitleaks 8.30.1 was run with full redaction on a tracked-file export and all reachable Git history;
category/location-only pattern scans supplemented it. Removed identifying values were not emitted
in audit reports, commit messages or PR prose.

Read-only GitHub checks covered repository metadata, paginated issue/PR descriptions, issue
comments, review comments and release descriptions. All 18 assets across the three existing beta
releases were downloaded without modifying remote state. Archive checksums were verified; archive
members and SBOM bytes were checked for the known identity/private-key patterns. Binary inspection
was a byte-pattern scan, not a proof that every embedded string or credential was identified.

## Verified defects and fixes

| Defect | Reproduction / regression evidence | Fix |
|---|---|---|
| An authorized lexical path could escape through a parent-directory symlink; `..` paths and empty authorization roots were unsafe | `filesystem::tests` and `path_policy::tests`: escape, traversal, empty-root and authorized-link boundary cases | Canonicalize the whole candidate against approved roots; reject lexical parent traversal and empty roots |
| Metadata errors were treated as missing; refused candidates and managed fragments could disappear, hiding incomplete coverage | Symlink-loop/permission tests, adapter candidate tests and managed-listing failure tests | Preserve unreadable/refused candidates, classify non-NotFound metadata errors as unreadable, and propagate checked enumeration errors into coverage gaps |
| Snapshot temporaries could reuse/truncate an existing predictable file; Unix permissions were tightened only after writing; create-new publication could replace a racing destination | `commands::snapshot_write_tests` collision, private-mode, injected failure and racing-destination cases | Exclusive temporary creation, Unix mode 0600 at creation, non-replacing hard-link publication, explicit-overwrite rename and owned-temporary cleanup |
| Snapshot output could accept special files or expose requested paths in its success message | Special-file and output-path regression cases | Refuse non-regular destinations and print a constant success message |
| Context and diff input reads bypassed regular-file checks and resource bounds | `tests/audit_cli.rs`: socket, escaping link and oversized input cases | Use checked, bounded regular-file reads rooted at the selected input's parent |
| Context deserialization/validation and argument parser diagnostics could echo hostile input | Context validation and argument-error regression cases | Keep fixed diagnostic text; do not export raw serde/clap error messages |
| Closed stdout caused a panic diagnostic | Closed-pipe integration regression | Handle output writes explicitly; a broken pipe exits successfully without panic output |
| `--no-env` still captured `PROGRAMDATA` in the context constructor | Isolated subprocess regression failed before the fix and covers disabled/enabled environment cases | Populate it only from the caller's captured allowlist |
| The initial diff hardening reused the 2 MiB configuration limit for larger generated reports | Independent review generated a 2.4 MiB snapshot from a valid small configuration and reproduced diff refusal | Separate 64 MiB report input/output policy shared by writer and reader; retain 2 MiB for context/configuration inputs |
| A generated local release binary embedded a private home prefix in compiler source paths | Category-only byte scan before and after a real remapped build | Build helper remaps home/repository prefixes; release CI invokes it |
| SBOM generation accepted a tag different from the crate version, could read a dependency's version and accepted substring tool-version matches | `scripts/test_generate_sbom.py`: failing-before package-section, mismatched-tag and exact-version cases | Reuse the package-scoped version reader, reject mismatches before tool invocation/output and require the exact pinned tool version |
| Local owner/group identifiers remained in tracked fuzz logs | Owner/group fields in `fuzz/results/fuzz-session.log` and `fuzz/results/session-1.log` | Replace only the six listing entries per file with neutral user/group placeholders; preserve technical evidence |
| Documentation overstated timing, action provenance and snapshot guarantees | Recorded benchmark versus README wording; actual action inventory versus maintaining guide | State measured timing, name the pinned third-party installer and document race/hard-link/durability limits |

## Privacy findings, retained identifiers and decisions

Current-file findings removed: local user/group ownership metadata in the two fuzz logs above.
A structural comparison confirmed that only those ownership fields changed. Known-identity scans
of current tracked content and generated site assets found no further candidates after the edits.

The Gitleaks candidate in `src/model/report.rs` is an intentional synthetic seeded token inside a
test module; its historical counterpart is also test data. Synthetic placeholder homes, fake
emails, hostile fuzz corpus strings, project URLs, upstream author attribution and required license
notices are retained. No confirmed live credential was found, so no specific credential rotation is
prescribed. That is not a guarantee that undetectable credentials do not exist.

Historical identifying information remains in earlier versions of:

- `docs/research/launch-audit-hygiene.md` and `docs/research/launch-audit-readme-dx.md`;
- `docs/engineering-verification.md`, `docs/verification-log.md`;
- `docs/research/evidence/fixture-run.txt` and `docs/research/run-fixtures.sh`;
- the two fuzz logs whose current ownership fields were sanitized.

Git author/committer names and contact identities also remain. The repository owner/account name
is retained in functional project URLs, notices and GitHub metadata. Whether to anonymize that
project identity, alter attribution or rewrite old identifying history is a user decision, not part
of this reversible patch. No history rewrite, force push, remote deletion or account-setting change
was performed. A privacy-fixing commit does not erase prior versions: Git history and the PR's
removed-line diff can still expose the old ownership fields. They are not repeated in PR prose.

## Unresolved limits and follow-up decisions

- Canonicalization/classification/open and directory listing are separate path-based operations.
  Concurrent hostile replacement of roots, ancestors or directory entries remains a TOCTOU risk.
  This is not a descriptor-relative sandbox. Scan stable, trusted trees and save snapshots to
  private, trusted directories.
- Create-new snapshot publication requires hard-link support and fails closed where it is absent.
  Explicit overwrite uses rename. Neither promises crash-durable storage. Windows ACL tightening
  remains unimplemented; cross-target checks are not hosted Windows/macOS runtime tests.
- Previously published `v0.1.0-beta.2` SBOM root versions do not match that release tag.
  All three `v0.1.0-beta.3` SBOM root versions match. Existing release assets were not replaced or
  deleted. Correcting old release assets, or publishing a new release containing these fixes,
  requires separate authorization.
- Local archive packaging accepts an already-built binary without inspecting its embedded version;
  the release workflow builds the reviewed commit first. Always build before local packaging.
- Path remapping is best-effort. Linker-generated PDB/OSO paths, strings generated by external tools
  and paths outside the remapped roots can remain. Ignored debug/intermediate Cargo caches were not
  comprehensively scrubbed and are not published by this PR. Inspect final distributed artifacts.
- Reachable fetched refs were checked, not deleted/unreachable objects, reflogs, other clones,
  forks, GitHub caches, workflow log/artifact contents, Discussions, Wiki or account-profile data.
  Remote text checks are pattern-based, not a comprehensive manual review of every public surface.
- This audit does not execute complete AI clients, establish upstream loader conformance,
  certify all platforms or prove the absence of bugs or personal information.
